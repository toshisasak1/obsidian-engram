# Configuration Reference

All Engram settings are stored in TOML format. Configuration is loaded with a layered resolution strategy, where each layer overrides the previous:

1. **Built-in defaults** (dataclass defaults in the source code)
2. **Global config** (`~/.config/engram/config.toml` on Linux/macOS, `%APPDATA%/engram/config.toml` on Windows)
3. **Project config** (`<vault>/.engram/config.toml`)
4. **Environment variables**
5. **CLI flags** (where applicable)

The project config file is auto-generated by `engram init`. You can edit it freely -- it is fully commented.

## Full config example

```toml
# Engram configuration
# https://github.com/toshisasak1/obsidian-engram

# Path to the SQLite database (relative to vault root).
db_path = ".engram/engram.db"

# Absolute path to the Obsidian vault root.
vault_path = "/home/you/my-vault"

# AI tool sources to index.
# Each [sources.<name>] section defines one tool.

[sources.claude]
enabled = true
path = "/home/you/.claude/projects"
parser = "claude"

[sources.codex]
enabled = true
path = "/home/you/.codex"
parser = "codex"

[sources.gemini]
enabled = true
path = "/home/you/.gemini/antigravity/brain"
parser = "gemini"

# Hybrid search tuning.
[search]
fts_limit_multiplier = 5
vector_limit_multiplier = 5
rrf_k = 60
half_life_days = 30.0

# Embedding backend.
[embedding]
enabled = false
provider = "local"
model = "all-MiniLM-L6-v2"
batch_size = 16
max_characters = 4000
# api_key = ""  # Or set ENGRAM_EMBEDDING_API_KEY env var.

# File-system watcher / poll settings.
[sync]
poll_interval_seconds = 30
settle_seconds = 8

# Auto-tagging. Assign tags to entries for filtered search.
# provider: "keyword" (rule-based), "cli" (claude/codex), "both".
[tagging]
enabled = false
provider = "keyword"
batch_size = 50
max_tags = 5

[tagging.cli]
command = "claude"
timeout = 120

# [tagging.rules]
# python = ["python", "pip", "venv", "pytest"]
# trading = ["forex", "gmma", "ema", "bot", "backtest"]

# Obsidian vault knowledge ingestion.
[vault_knowledge]
enabled = true
include = ["**/*.md"]
exclude = ["**/node_modules/**", "**/.obsidian/**", "**/.engram/**", "**/.smart-env/**", "**/.git/**"]
```

## Top-level settings

### `db_path`

- **Type**: string (file path)
- **Default**: `".engram/engram.db"`
- **Description**: Path to the SQLite database. Relative paths are resolved against the vault root. Can be absolute.
- **Env override**: `ENGRAM_DB_PATH`

### `vault_path`

- **Type**: string (directory path) or omitted
- **Default**: auto-detected from current directory
- **Description**: Root of the Obsidian vault. Used for vault knowledge indexing and path resolution. When omitted, Engram walks upward from the current directory looking for `.obsidian/` or `.engram/`.
- **Env override**: `ENGRAM_VAULT_PATH`

## `[sources.<name>]` -- AI tool sources

Each source is defined as a TOML table under `[sources]`. The table name (e.g., `claude`, `codex`, `gemini`) identifies the source.

### `enabled`

- **Type**: boolean
- **Default**: `true`
- **Description**: Set to `false` to skip this source during sync without removing its config.

### `path`

- **Type**: string (directory path)
- **Default**: auto-detected platform path
- **Description**: Root directory for this source's data files. The parser discovers individual files under this root. Supports `~` for the home directory.

Default paths by source:

| Source | Default path |
|--------|-------------|
| `claude` | `~/.claude/projects` |
| `codex` | `~/.codex` |
| `gemini` | `~/.gemini/antigravity/brain` |

### `parser`

- **Type**: string
- **Default**: same as the source name
- **Description**: Which parser to use for this source. Built-in parsers: `claude`, `codex`, `gemini`, `vault`, `vscode`. Third-party parsers registered via `entry_points` are also available.

You can reuse parsers for custom sources:

```toml
[sources.work_claude]
enabled = true
path = "/work/shared/.claude/projects"
parser = "claude"
```

### Adding a custom source

Any directory can be added as a source by specifying a `path` and `parser`:

```toml
[sources.my_tool]
enabled = true
path = "/path/to/my/tool/data"
parser = "vault"  # Uses the vault parser for .md files
```

## `[search]` -- Search tuning

### `fts_limit_multiplier`

- **Type**: integer
- **Default**: `5`
- **Description**: The FTS5 query fetches `limit * fts_limit_multiplier` candidates before RRF fusion. Higher values give more candidates to fuse, improving recall at the cost of speed.

### `vector_limit_multiplier`

- **Type**: integer
- **Default**: `5`
- **Description**: Same as `fts_limit_multiplier` but for the vector search branch. Only used when embeddings are enabled.

### `rrf_k`

- **Type**: integer
- **Default**: `60`
- **Description**: The constant `K` in the Reciprocal Rank Fusion formula: `score = 1 / (K + rank)`. Controls how aggressively top-ranked results dominate.

| Value | Behavior |
|-------|----------|
| Low (10-30) | Top results from each method dominate heavily. Good when one method is much more reliable. |
| Medium (50-70) | Balanced blending. Good default. |
| High (100+) | Very smooth blending. Results from both methods get similar weight regardless of rank. |

### `half_life_days`

- **Type**: float
- **Default**: `30.0`
- **Description**: Time decay half-life in days. After this many days, a result's score is halved. Controls how quickly old conversations fade relative to recent ones.

| Value | Behavior |
|-------|----------|
| 7.0 | Aggressive recency bias. Week-old content scores 50% of today's. |
| 30.0 | Moderate decay. Good for active projects. |
| 90.0 | Gentle decay. Old conversations remain relevant for months. |
| 365.0 | Near-flat weighting. Everything is roughly equal regardless of age. |

The formula is: `multiplier = 0.5 ^ (age_days / half_life_days)`, clamped to `[0.01, 1.0]`.

## `[embedding]` -- Vector embeddings

### `enabled`

- **Type**: boolean
- **Default**: `false`
- **Description**: Set to `true` to enable vector semantic search alongside FTS5 keyword search. Requires the appropriate optional dependencies.

### `provider`

- **Type**: string
- **Default**: `"local"`
- **Options**: `"local"`, `"openai"`, `"voyage"`, `"none"`
- **Description**: Which embedding backend to use.

| Provider | Install command | Notes |
|----------|----------------|-------|
| `local` | `pip install obsidian-engram[embeddings]` | Uses `sentence-transformers`. Runs on CPU. No API key needed. |
| `openai` | `pip install obsidian-engram[openai]` | Uses OpenAI Embeddings API. Requires API key. |
| `voyage` | `pip install obsidian-engram[openai]` | Uses Voyage AI API (OpenAI-compatible). Requires API key. |
| `none` | -- | Explicitly disables embeddings even if `enabled = true`. |

### `model`

- **Type**: string
- **Default**: `"all-MiniLM-L6-v2"`
- **Description**: Model name passed to the embedding provider.

Recommended models by provider:

| Provider | Model | Dimensions | Notes |
|----------|-------|------------|-------|
| `local` | `all-MiniLM-L6-v2` | 384 | Fast, lightweight, good quality |
| `local` | `all-mpnet-base-v2` | 768 | Higher quality, slower |
| `openai` | `text-embedding-3-small` | 1536 | Good balance of cost and quality |
| `openai` | `text-embedding-3-large` | 3072 | Highest quality |
| `voyage` | `voyage-3` | 1024 | Voyage AI's latest |

### `batch_size`

- **Type**: integer
- **Default**: `16`
- **Description**: Number of entries to embed in a single batch during sync. Larger batches are faster but use more memory (for local) or more API quota (for cloud).

### `max_characters`

- **Type**: integer
- **Default**: `4000`
- **Description**: Maximum text length (in characters) per entry before truncation for embedding. Longer texts are truncated from the right.

### `api_key`

- **Type**: string
- **Default**: `""`
- **Description**: API key for the `openai` or `voyage` provider. Prefer using the `ENGRAM_EMBEDDING_API_KEY` environment variable instead of storing the key in the config file.
- **Env override**: `ENGRAM_EMBEDDING_API_KEY`

## `[sync]` -- Watch and polling

### `poll_interval_seconds`

- **Type**: integer
- **Default**: `30`
- **Description**: How often (in seconds) `engram watch` polls for file changes.

### `settle_seconds`

- **Type**: integer
- **Default**: `8`
- **Description**: Minimum age (in seconds) a file must have before it is eligible for sync. This prevents indexing files that are still being written by another process.

If you see partially indexed sessions, increase this value:

```toml
[sync]
settle_seconds = 15
```

## `[tagging]` -- Auto-tagging

Configure automatic tagging of indexed entries. See [Auto-Tagging](tagging.md) for a full guide.

### `enabled`

- **Type**: boolean
- **Default**: `false`
- **Description**: Enable the tagging feature.

### `provider`

- **Type**: string
- **Default**: `"keyword"`
- **Options**: `"keyword"`, `"cli"`, `"both"`
- **Description**: Which tagging backend to use.

| Provider | Description |
|----------|-------------|
| `keyword` | Rule-based pattern matching (free, instant) |
| `cli` | AI tagging via `claude -p` / `codex -q` (account subscription only) |
| `both` | Run keyword first, then CLI for additional tags |

### `batch_size`

- **Type**: integer
- **Default**: `50`
- **Description**: Maximum entries to process per tagging run.

### `max_tags`

- **Type**: integer
- **Default**: `5`
- **Description**: Maximum number of tags per entry.

### `[tagging.cli]`

CLI backend settings:

```toml
[tagging.cli]
command = "claude"   # "claude" or "codex"
timeout = 120        # seconds per batch
```

### `[tagging.rules]`

Custom keyword rules. The key name becomes the tag, and the value is an array of keywords to match:

```toml
[tagging.rules]
python = ["python", "pip", "venv", "pytest"]
trading = ["forex", "gmma", "ema", "bot", "backtest"]
```

## `[vault_knowledge]` -- Vault document indexing

### `enabled`

- **Type**: boolean
- **Default**: `true`
- **Description**: When `true`, Obsidian vault markdown files are indexed alongside AI conversation logs.

### `include`

- **Type**: array of glob strings
- **Default**: `["**/*.md"]`
- **Description**: File patterns to include. Uses Python `glob` syntax.

Examples:

```toml
include = ["**/*.md"]                    # All markdown files (default)
include = ["notes/**/*.md"]              # Only files under notes/
include = ["**/*.md", "**/*.txt"]        # Markdown and text files
```

### `exclude`

- **Type**: array of glob strings
- **Default**: `["**/node_modules/**", "**/.obsidian/**", "**/.engram/**", "**/.smart-env/**", "**/.git/**"]`
- **Description**: Directory patterns to exclude from vault indexing. Matched against path components.

To add your own exclusions without losing the defaults, list them all:

```toml
exclude = [
    "**/node_modules/**",
    "**/.obsidian/**",
    "**/.engram/**",
    "**/.smart-env/**",
    "**/.git/**",
    "**/archive/**",
    "**/drafts/**",
]
```

## Environment variables

| Variable | Overrides | Description |
|----------|-----------|-------------|
| `ENGRAM_DB_PATH` | `db_path` | Absolute path to the database file |
| `ENGRAM_VAULT_PATH` | `vault_path` | Absolute path to the vault root |
| `ENGRAM_EMBEDDING_API_KEY` | `embedding.api_key` | API key for OpenAI or Voyage embeddings |

Environment variables always win over both global and project config.

## Global config

The global config file applies defaults across all your vaults. Its location depends on your platform:

| Platform | Path |
|----------|------|
| Linux / macOS | `~/.config/engram/config.toml` |
| Windows | `%APPDATA%\engram\config.toml` |

This is useful for setting a shared embedding API key or default search parameters:

```toml
# ~/.config/engram/config.toml (global)

[embedding]
enabled = true
provider = "local"

[search]
half_life_days = 60.0
```

Project-level settings in `.engram/config.toml` override these defaults.

## Config resolution example

Suppose you have:

- **Global config**: `rrf_k = 40`, `half_life_days = 60`
- **Project config**: `rrf_k = 80`
- **No env vars**

The resolved search config will be: `rrf_k = 80` (from project), `half_life_days = 60` (from global). The project config overrides matching keys; unset keys fall through to the global config.

## Tips

- After changing config, run `engram sync` to reindex with the new settings. FTS settings take effect immediately on the next search. Embedding config changes only affect newly embedded entries.
- Use `engram status --json` to verify the active configuration and database state.
- You can safely delete `.engram/engram.db` and re-run `engram sync` to rebuild the entire index from scratch.
