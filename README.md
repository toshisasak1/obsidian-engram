# Obsidian Engram

**[English](#obsidian-engram) | [日本語](#obsidian-engram-1)**

Persistent memory for AI tools. Unify every conversation from Claude, Codex, Gemini, and your IDE into a single searchable knowledge base -- right inside your Obsidian vault.

[![Python 3.10+](https://img.shields.io/badge/python-3.10%2B-blue.svg)](https://www.python.org/downloads/)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)
[![PyPI](https://img.shields.io/pypi/v/obsidian-engram.svg)](https://pypi.org/project/obsidian-engram/)

## The Problem

AI assistants forget everything between sessions. You solved a gnarly bug with Claude last Tuesday, refined a deployment strategy with Codex on Thursday, and explored architecture trade-offs with Gemini over the weekend. On Monday, every tool starts from zero.

Your conversations hold real knowledge -- decisions, context, working solutions -- scattered across tool-specific formats that no tool can search.

## The Solution

Engram gives your AI tools a shared memory. It ingests conversation logs from every major AI CLI, indexes them with hybrid full-text and vector search, and exposes the results through MCP so any AI tool can recall what you discussed before.

It runs entirely on your machine. No cloud. No API keys required. Just a SQLite database and a CLI.

## Features

- **Hybrid search** -- FTS5 keyword search + vector cosine similarity, fused with Reciprocal Rank Fusion and weighted by time decay. Recent conversations surface first; old ones fade gracefully.
- **Multi-source** -- Parsers for Claude Code, Codex CLI, Gemini CLI, VS Code conversations, and Obsidian vault documents. One index across all of them.
- **CJK ready** -- Trigram tokenizer handles Japanese, Chinese, and Korean without word-boundary hacks.
- **MCP integration** -- Four tools (`memory_search`, `memory_brief`, `memory_status`, `memory_list_sessions`) that any MCP-compatible AI client can call.
- **Works with any vault** -- Drop into an existing Obsidian vault or run standalone.
- **Privacy-first** -- Everything local. No telemetry. No cloud dependency.
- **Extensible** -- Third-party parsers can register via `entry_points`. Write a parser, publish a package.

## Quick Start

```bash
pip install obsidian-engram
```

Initialize in your Obsidian vault (or any directory):

```bash
cd ~/my-vault
engram init
```

This auto-detects installed AI tools, creates `.engram/config.toml`, sets up the database, and runs the first sync.

Sync new conversations:

```bash
engram sync
```

Search your memory:

```bash
engram search "deployment strategy for the API gateway"
```

## How It Works

```
Sources                    Index                     Output
---------                  -----                     ------
Claude Code  ----+
Codex CLI    ----|
Gemini CLI   ----|----->  SQLite DB  ------------>  CLI search
VS Code      ----|        FTS5 (trigram)            MCP tools
Vault .md    ----+        + Vector (optional)       Session briefs
                          + Time decay
```

1. **Ingest**: Parsers read JSONL conversation logs and Markdown files from each tool's data directory.
2. **Index**: Messages are stored in SQLite with FTS5 full-text indexing (trigram tokenizer for CJK support). Optional vector embeddings add semantic search.
3. **Search**: Queries hit both FTS5 and vector indexes. Results are merged via Reciprocal Rank Fusion (`score = 1/(K + rank)`), then weighted by exponential time decay (`0.5 ^ (age / half_life)`).
4. **Serve**: The MCP server exposes search over stdio so AI tools can query memory mid-conversation.

## CLI Commands

| Command | Description |
|---------|-------------|
| `engram init` | Initialize database and config. Auto-detects sources. |
| `engram sync` | Sync all source files into the database. |
| `engram search <query>` | Hybrid search across all indexed content. |
| `engram brief` | Generate a context brief for the current workspace. |

## MCP Integration

Add to your Claude Code settings (`.claude/settings.json` or global MCP config):

```json
{
  "mcpServers": {
    "engram": {
      "command": "engram",
      "args": ["mcp"],
      "env": {}
    }
  }
}
```

The MCP server exposes four tools:

| Tool | Description |
|------|-------------|
| `memory_search` | Free-text search with optional source filter |
| `memory_brief` | Workspace-aware context brief with recent sessions |
| `memory_status` | Database statistics |
| `memory_list_sessions` | Browse recent sessions by source |

## Configuration

All settings live in `.engram/config.toml`, generated by `engram init`. Key sections:

```toml
# Source paths (auto-detected)
[sources.claude]
enabled = true
path = "~/.claude/projects"

[sources.codex]
enabled = true
path = "~/.codex"

# Search tuning
[search]
rrf_k = 60                 # RRF constant (higher = smoother blending)
half_life_days = 30.0       # Time decay half-life

# Vector embeddings (off by default)
[embedding]
enabled = false
provider = "local"          # "local", "openai", "voyage", "none"
model = "all-MiniLM-L6-v2"

# Vault knowledge indexing
[vault_knowledge]
enabled = true
include = ["**/*.md"]
```

Environment variables `ENGRAM_DB_PATH`, `ENGRAM_VAULT_PATH`, and `ENGRAM_EMBEDDING_API_KEY` override config values.

## Identity Framework

`engram init` copies four template files into your vault root:

| File | Purpose |
|------|---------|
| `SOUL.md` | AI assistant identity and principles |
| `USER.md` | About you -- context for AI to personalize |
| `AGENTS.md` | Session startup checklist |
| `TOOLS.md` | Local environment documentation |

These files persist across sessions. AI tools that read vault files will pick them up automatically. Edit them freely -- they are yours.

## Vault Structure

After initialization, your vault gains:

```
your-vault/
  .engram/
    config.toml          # Configuration
    engram.db            # SQLite database (FTS5 + optional vectors)
  SOUL.md                # AI identity (template)
  USER.md                # Your profile (template)
  AGENTS.md              # Session startup (template)
  TOOLS.md               # Environment docs (template)
```

The `.engram/` directory can be gitignored. The identity files are meant to be versioned.

## Embedding Options

Engram works out of the box with FTS5-only search (no extra dependencies). For semantic vector search, choose a backend:

| Option | Install | Notes |
|--------|---------|-------|
| FTS5 only (default) | `pip install obsidian-engram` | Trigram matching, no model download |
| Local model | `pip install obsidian-engram[embeddings]` | Uses `all-MiniLM-L6-v2`, ~80MB download, runs on CPU |
| OpenAI API | `pip install obsidian-engram[openai]` | Requires `ENGRAM_EMBEDDING_API_KEY` |
| Voyage API | `pip install obsidian-engram[openai]` | Set provider to `voyage` in config |

Enable in config:

```toml
[embedding]
enabled = true
provider = "local"
```

## Requirements

- Python 3.10+
- SQLite with FTS5 (included in standard Python builds)
- Obsidian (optional -- works standalone too)

# Obsidian Engram

**[English](#obsidian-engram) | [日本語](#obsidian-engram-1)**

AIツールに永続メモリを。Claude、Codex、Gemini、IDEの全会話を一つの検索可能なナレッジベースに統合します。Obsidian Vaultの中で、完全にローカルで動作します。

[![Python 3.10+](https://img.shields.io/badge/python-3.10%2B-blue.svg)](https://www.python.org/downloads/)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)
[![PyPI](https://img.shields.io/pypi/v/obsidian-engram.svg)](https://pypi.org/project/obsidian-engram/)

## 課題

AIアシスタントはセッション間で全てを忘れます。火曜にClaudeで解決した厄介なバグ、木曜にCodexで練ったデプロイ戦略、週末にGeminiで検討したアーキテクチャ。月曜にはどのツールもゼロからのスタートです。

会話の中には本物の知識 -- 決定事項、文脈、動くソリューション -- が詰まっています。それがツール固有のフォーマットに散在し、横断検索できない状態にあります。

## 解決策

Engramは、AIツールに共有メモリを与えます。主要なAI CLIの会話ログを取り込み、全文検索とベクトル検索のハイブリッドでインデックスし、MCPを通じて検索結果を公開します。どのAIツールからでも、過去に話した内容を思い出せるようになります。

全てローカルで動作します。クラウド不要。APIキー不要。SQLiteデータベースとCLIだけです。

## 特徴

- **ハイブリッド検索** -- FTS5キーワード検索 + ベクトルコサイン類似度をReciprocal Rank Fusionで統合し、時間減衰で重み付け。最近の会話が優先的に浮上し、古いものは緩やかに沈降します。
- **マルチソース** -- Claude Code、Codex CLI、Gemini CLI、VS Code、Obsidian Vault文書のパーサーを内蔵。一つのインデックスで横断検索。
- **CJK対応** -- trigramトークナイザにより、日本語・中国語・韓国語を単語境界の問題なく処理。
- **MCP連携** -- 4つのツール（`memory_search`、`memory_brief`、`memory_status`、`memory_list_sessions`）をMCP対応のAIクライアントから呼び出し可能。
- **既存Vaultに追加可能** -- 既存のObsidian Vaultにそのまま導入。スタンドアロン動作も可。
- **プライバシー優先** -- 全てローカル処理。テレメトリなし。クラウド依存なし。
- **拡張可能** -- サードパーティのパーサーを`entry_points`経由で登録可能。

## 仕組み

```
ソース                     インデックス               出力
---------                  -----                     ------
Claude Code  ----+
Codex CLI    ----|
Gemini CLI   ----|----->  SQLite DB  ------------>  CLI検索
VS Code      ----|        FTS5 (trigram)            MCPツール
Vault .md    ----+        + Vector (オプション)      セッションブリーフ
                          + 時間減衰
```

1. **取込**: パーサーが各ツールのJSONL会話ログとMarkdownファイルを読み取り。
2. **索引**: SQLiteにFTS5全文検索インデックス付きで格納（CJK対応のtrigramトークナイザ）。オプションのベクトル埋め込みでセマンティック検索も追加可能。
3. **検索**: クエリはFTS5とベクトルインデックスの両方にヒット。Reciprocal Rank Fusion（`score = 1/(K + rank)`）で統合後、指数時間減衰（`0.5 ^ (経過日数 / 半減期)`）で重み付け。
4. **配信**: MCPサーバーがstdio経由で検索を公開。AIツールが会話中にメモリを参照可能。

## アイデンティティフレームワーク

`engram init` は4つのテンプレートファイルをVaultルートにコピーします:

| ファイル | 用途 |
|---------|------|
| `SOUL.md` | AIアシスタントのアイデンティティと行動指針 |
| `USER.md` | あなたについて -- AIがパーソナライズするための文脈 |

## Vault構造

初期化後のVault構成:

```
your-vault/
  .engram/
    config.toml          # 設定

`.engram/` ディレクトリはgitignore可能です。アイデンティティファイルはバージョン管理を推奨します。

| OpenAI API | `pip install obsidian-engram[openai]` | `ENGRAM_EMBEDDING_API_KEY` が必要 |

```
